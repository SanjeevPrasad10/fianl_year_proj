Abstract (150 Words)

Centralized cryptocurrency management exposes digital assets to catastrophic counterparty vulnerabilities, structural insolvency, and unauthorized credential exposure. This project develops a production-grade, full-stack, non-custodial multi-currency Web3 wallet operating on the Ethereum Sepolia testnet. Built using React.js, Node.js, Express.js, MongoDB, and Ethers.js v6, the architecture enforces strict client-side sovereignty: 12-word BIP-39 mnemonic recovery phrases, private keys, and transaction signatures are computed exclusively within the browser's isolated runtime. Sensitive key material is encrypted using Scrypt key derivation and AES-128-CTR ciphers before generating encrypted keystores. The backend stores only zero-knowledge ciphertext, transaction metadata, and contact directories, completely isolating the database from unencrypted secrets. Features include real-time portfolio valuation via CoinGecko, dynamic EIP-1559 gas fee estimation, vector QR code generation, address book auto-fill, and session locking. Black-box testing across 20 rigorous functional scenarios verified a 100% pass rate, providing enterprise-grade security and frictionless cross-device accessibility for modern decentralized financial systems.

CHAPTER 1: INTRODUCTION

1.1 Background and Motivation

Over the preceding decade, public blockchain networks have matured from experimental cryptographic protocols into foundational components of international decentralized finance. Unlike traditional financial architectures where private bank ledgers maintain absolute custodial authority over customer balances, public blockchains operate as deterministic, distributed state machines. In these networks, accounts are represented through public-key cryptography.

Every digital wallet consists of an asymmetric cryptographic pair: a public address used as the destination identifier for receiving capital, and a 256-bit secret private key that confers mathematically absolute authorization to sign outbound transactions. Despite the sovereign promise of Web3, the majority of retail participants interface with cryptocurrencies through centralized custodial platforms where third parties hold their private keys. When centralized custodians suffer security intrusions, regulatory freezes, or insolvency (such as the collapse of FTX in 2022), user funds are permanently lost. This vulnerability popularized the fundamental Web3 doctrine: "Not your keys, not your coins."

1.2 Problem Statement

Existing digital asset custody solutions suffer from three structural flaws: 1) Custodial Counterparty Vulnerabilities: Centralized databases act as attack honeypots; 2) Device Isolation: Local extension wallets lock users to a single PC without automated secure cloud recovery; 3) Typographical Loss: Manual entry of 42-character hexadecimal addresses frequently results in irreversible asset loss.

1.2.1 Core Vulnerabilities in Centralized Custody

Centralized custodians store unencrypted private keys or database balance records on internal servers. An attacker gaining root database access or executing an insider exploit can instantly drain all registered user funds. In contrast, non-custodial systems isolate secrets exclusively to client-side hardware.

1.3 Objectives of the Project

  • Generate deterministic 12-word BIP-39 mnemonic seed phrases in browser volatile memory.
  • Perform client-side Web3 keystore encryption using Scrypt key derivation and AES-128-CTR.
  • Implement a zero-knowledge cloud backup subsystem in MongoDB for multi-device portability.
  • Support native Ethereum (ETH) alongside ERC-20 smart contract tokens (Circle USDC and Chainlink LINK).
  • Provide dynamic EIP-1559 gas fee estimation and live USD portfolio tracking.
  • Develop an integrated contact directory to prevent 42-character address typographical errors.

1.4 Scope of the Project

The scope encompasses full-stack MERN Web3 development, deployment on the Ethereum Sepolia testnet (Chain ID 11155111), and 20-scenario black-box functional validation.

CHAPTER 2: LITERATURE SURVEY

2.1 Evolution of Cryptocurrency Wallets

Cryptocurrency wallet architectures have evolved from non-deterministic JBOK ("Just a Bunch of Keys") files into modern Hierarchical Deterministic (HD) wallets governed by Bitcoin Improvement Proposals BIP-32 and BIP-39. Under BIP-39, 128 bits of entropy map to 12 English dictionary words, which derive a 512-bit binary master seed through PBKDF2 with HMAC-SHA512.

2.2 Cryptographic Standards: BIP-39, BIP-32, secp256k1

Ethereum utilizes the Koblitz curve secp256k1 (defined by y² = x³ + 7 mod p) for key derivation and ECDSA transaction signing. The public key point K is computed via scalar multiplication of the private key integer k with the generator point G: K = k × G.

CHAPTER 3: METHODOLOGY

3.1 Software Development Life Cycle (SDLC) Model

The project followed the Agile Iterative SDLC model across three 24-hour sprints: Sprint 1 implemented the cryptographic engine and Express/MongoDB backend; Sprint 2 integrated Ethers.js v6 with Sepolia JSON-RPC nodes and ERC-20 tokens; Sprint 3 hardened session locking and executed 20 black-box functional validations.

3.2 Non-Custodial Architecture & Zero-Knowledge Principle

The architecture enforces a strict Zero-Knowledge boundary: the backend server and database never receive, process, or store unencrypted private keys, mnemonic phrases, or wallet passwords.

3.3 Key Derivation & Client-Side Encryption Workflow

The client encrypts the raw private key using Scrypt key derivation (N=8192, r=8, p=1, dkLen=32) and AES-128-CTR symmetric counter mode:

DerivedKey = Scrypt(Password, Salt, N=8192, r=8, p=1, dkLen=32) Ciphertext = AES-128-CTR(DerivedKey[0..15], PrivateKey) MAC = Keccak-256(DerivedKey[16..31] || Ciphertext)

3.4 Dynamic Gas Estimation & Signing Mechanics

The client calculates the network fee in real time: Total Fee = Gas Limit × Gas Price. For native ETH transfers, Gas Limit is fixed at 21,000 units. For ERC-20 token transfers, dynamic gas estimation is queried via JSON-RPC with a +20% safety margin.

3.5 Encrypted Keystore Synchronization Protocol

When a user logs in from a new machine, the client retrieves the encrypted JSON keystore from MongoDB via GET /api/wallet. The user inputs their wallet password, triggering local in-browser Scrypt decryption without server involvement.

CHAPTER 6: CONCLUSION

This project successfully implemented and benchmarked a non-custodial multi-currency Web3 wallet on the Ethereum Sepolia network. By uniting client-side key isolation (BIP-39, Scrypt, AES-128-CTR) with cloud persistence (Express.js, MongoDB), the system achieves true self-sovereignty without sacrificing modern multi-device convenience.
