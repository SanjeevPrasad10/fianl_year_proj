1. Introduction & Problem Statement

Speaker: Member 1 (Team Leader)
Addressing the catastrophic security single points of failure in centralized digital asset custody

The Centralized Custody Hazard (CEXs)

Over 70% of crypto users store funds on centralized exchanges where they do not possess their keys:

  • "Not Your Keys, Not Your Coins": Users hold promissory ledger rows on central databases. Private keys remain with the custodian.
  • Catastrophic Historic Insolvencies: FTX ($8.9B lost), Mt. Gox ($460M stolen), Celsius ($4.7B deficit) proved custodians can freeze or lose assets without warning.
  • Single Point of Failure: Centralized databases attract APT hacks, SQL injection, credential stuffing, and insider embezzlement.

The Non-Custodial Solution Paradigm

We engineered a self-sovereign web wallet where user autonomy is mathematically enforced:

  • Client-Side Cryptographic Sovereignty: Seed generation, key derivation, and transaction signing occur strictly in browser RAM.
  • Zero-Knowledge Application Server: The Node/Express backend never sees, handles, or stores plaintext private keys or seed phrases.
  • Memory-Hard Key Encryption: Scrypt KDF + AES-128-CTR protects keystores against offline dictionary & GPU brute-force attacks.

4. Cryptographic Derivation Pipeline

Speaker: Member 2 (Frontend & Crypto)
Mathematical progression from raw cryptographic entropy to deterministic Ethereum public addresses

BIP-39 & BIP-44 Mathematical Flow

  • 1. Entropy Sampling: CSPRNG generates 128 bits of true entropy: E ∈ {0, 1}^128
  • 2. Checksum Calculation: SHA-256 hash yields 4-bit checksum: CS = MSB_4(SHA-256(E))
  • 3. 12-Word Mnemonic: 132 bits split into 12 segments of 11 bits, mapped to the standard 2,048-word BIP-39 English dictionary.
  • 4. PBKDF2 Seed Generation: Transformed into 512-bit binary seed via PBKDF2 using 2,048 rounds of HMAC-SHA512.
  • 5. BIP-44 Derivation: Primary Ethereum private key derived along standard path: m / 44' / 60' / 0' / 0 / 0

Secp256k1 & Keccak-256 Address Generation

  • Elliptic Curve Equation: Secp256k1 short Weierstrass form:
    y^2 ≡ x^3 + 7 (mod p)
  • Public Key Derivation: Scalar multiplication with generator point G:
    K = k × G (Discrete Logarithm hardness).
  • Uncompressed Serialization: Public key coordinate bytes (x || y) concatenated (64 bytes).
  • Ethereum Address Derivation: Keccak-256 hash truncated to least significant 20 bytes:
    Address = "0x" || LSB_20(Keccak-256(x || y))

5. Client-Side Encryption & Security Model

Speaker: Member 2 (Frontend & Crypto)
Protecting private keys at rest via memory-hard Scrypt KDF, AES-128-CTR, and MAC integrity verification

1. Memory-Hard Scrypt KDF

Neutralizing GPU and ASIC brute-force parallel cracking:

  • Cost Parameters: N = 131,072, r = 8, p = 1.
  • RAM Allocation: Demands 128 MB RAM per guess, rendering mass parallel hardware attacks non-viable.
  • Generates 32-byte Derived Key split into Cipher Key & MAC Key.

2. AES-128-CTR Cipher

Military-grade symmetric encryption of private key:

  • Encrypted in Counter (CTR) mode with 16-byte random IV.
  • Integrity MAC: Keccak-256(MK || Ciphertext)
  • Prevents padding oracle attacks and immediately detects wrong unlock passwords.

3. Dual-Password Model

Complete separation of portal access from cryptographic authority:

  • Portal Password: Hashed with bcrypt (10 rounds) for website authentication.
  • Wallet Password: Exclusively used in browser memory for Scrypt key derivation.
  • Server database leak cannot decrypt funds.

6. Blockchain Operations & Gas Mechanics

Speaker: Member 3 (Blockchain Specialist)
Executing real-time transactions on Ethereum Sepolia Testnet with EIP-1559 dynamic fee optimization

EIP-1559 Dynamic Fee Calculation

Algorithmic gas optimization replacing legacy first-price auctions:

  • Total Max Fee Formula: Max Fee = (2 × Base Fee) + Max Priority Fee
  • Base Fee: Calculated algorithmically by EVM block congestion and burned. Queried dynamically via eth_feeHistory.
  • Priority Fee (Tip): Paid directly to proof-of-stake validators to guarantee block priority.
  • Gas Limits:
    • Native ETH Transfer: Fixed at 21,000 units (100% efficient).
    • ERC-20 Tokens: Dynamically estimated via contract.estimateGas.transfer() with a 20% safety margin (~46,000 units).

Sepolia Testnet & Smart Contract Infrastructure

  • Network Target: Ethereum Sepolia Testnet (Chain ID: 11155111) with high-availability Infura/Alchemy JSON-RPC endpoints.
  • EIP-155 Replay Protection: Chain ID embedded into ECDSA signature payload prevents replay on mainnet or other testnets.
  • ERC-20 ABI Interfacing: Read-only eth_call for balanceOf() and signed state-modifying transfer(address,uint256) calls.
  • Live Portfolio Valuation: Real-time USD conversion via CoinGecko REST API with fallback caching.

10. Future Roadmap & Scalability

Speaker: Member 4 (Backend Lead)
Next-generation Web3 paradigms: Account Abstraction, Threshold Signatures, and Layer-2 Rollups

1. ERC-4337 Account Abstraction

Smart contract wallets with programmable rules:

2. Multi-Party Computation (MPC)

Threshold Signature Schemes (TSS):

  • Private key split into 3 mathematical secret shares (2-of-3 threshold).
  • Share 1 on client, Share 2 on server, Share 3 on backup device.
  • Private key is never assembled in complete form anywhere.

Hardware security and high scalability:
